# Админка сайта kendo-baikal.ru

Админка — это страница **https://kendo-baikal.ru/admin/**. Через неё редакторы добавляют новости и правят страницы, не трогая код. Сервера и базы данных у админки нет: каждое сохранение — это обычный коммит в репозиторий `tulubyev/kendo-baikal` на GitHub, после чего сайт пересобирается автоматически.

## Почему Sveltia CMS (для разработчиков)

| | |
|---|---|
| Выбор | **Sveltia CMS 0.229.0** (npm `@sveltia/cms`), формат `config.yml` совместим с Decap CMS |
| Почему | Статический SPA: 0 МБ памяти на VPS, нет OAuth-прокси и отдельного контейнера. Есть русская локаль (`locale: ru`), вход в GitHub по персональному токену (PAT) без серверной части, транслитерация кириллицы в slug (используется `@sindresorhus/transliterate`) |
| Почему не Decap | Decap для входа через GitHub требует OAuth-прокси (ещё один контейнер на перегруженном VPS) |
| Версия | Закреплена в `public/admin/index.html` (`unpkg.com/@sveltia/cms@0.229.0/...`) + SRI-хэш `integrity`: подмена файла на CDN не пройдёт. Локали и вспомогательные чанки CMS сама подтягивает с unpkg (версия та же) — поэтому в CSP `/admin/` разрешён `unpkg.com`, остальной сайт ничего внешнего не грузит |
| Режим публикации | `publish_mode: simple` — прямой коммит в `main`. `editorial_workflow` не включён: для небольшого клуба он добавляет PR/ветки и путаницу, а откатить ошибочную правку можно через историю Git |
| Вход | Персональный токен GitHub (fine-grained PAT). OAuth не используется |

Поля коллекций строго соответствуют контракту frontmatter из `docs/PLAN.md` и схемам `src/content.config.ts`. **Если меняете поля — меняйте и схему Astro, и `public/admin/config.yml` одновременно.**

### Обновление CMS

```bash
npm view @sveltia/cms version                       # новая версия
npm pack @sveltia/cms@X.Y.Z && tar xzf sveltia-cms-X.Y.Z.tgz
echo sha384-$(openssl dgst -sha384 -binary package/dist/sveltia-cms.js | openssl base64 -A)
```
Подставьте версию и хэш в `public/admin/index.html`, проверьте вход и создание тестовой записи.

## Для редакторов

### 1. Как получить доступ

1. Скажите владельцу сайта своё имя пользователя на GitHub (зарегистрироваться на github.com бесплатно).
2. Владелец пригласит вас в репозиторий. Вам придёт письмо — нажмите **Accept invitation**.
3. Создайте **токен доступа** (делается один раз):
   - GitHub → ваш аватар → **Settings** → **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**.
   - *Resource owner* — владелец репозитория (`tulubyev`); *Repository access* — **Only select repositories** → `kendo-baikal`.
   - *Permissions* → *Repository permissions* → **Contents: Read and write**. Больше ничего не нужно.
   - Срок действия — на ваше усмотрение (например, 1 год). Скопируйте токен (`github_pat_…`) — повторно он не показывается.
4. Откройте https://kendo-baikal.ru/admin/ → **Sign in with GitHub using Token** → вставьте токен. Браузер запомнит вход.

Токен — это ваш пароль. Никому его не отправляйте и не публикуйте. Если потеряли или показали кому-то — отзовите на GitHub (Settings → Developer settings → Personal access tokens) и создайте новый.

### 2. Как создать новость (пост)

1. В админке слева выберите **Новости (записи)** → кнопка **Создать**.
2. Заполните: **Заголовок** и **Дату публикации** (обязательно), по желанию — краткое описание, рубрику, метки, обложку.
3. В поле **Текст записи** напишите текст. Кнопки над полем — заголовки, списки, ссылки, картинки.
4. Если запись ещё не готова — включите переключатель **Черновик**. Черновик не появится на сайте.
5. Нажмите **Сохранить**/**Опубликовать**. Адрес записи создаётся из заголовка автоматически (русские буквы превращаются в латинские): `/news/<адрес>/`.

### 3. Как загрузить картинку

- В поле **Обложка** (или кнопкой «картинка» в тексте) нажмите **Выбрать файл** → **Загрузить** и выберите файл с компьютера.
- Картинка сохранится в папку `/uploads/` в репозитории. Перед загрузкой уменьшите фото (достаточно ширины 1600 px и размера до 500 КБ — сайт быстрее, а репозиторий не раздувается).
- Имена файлов — латиницей, без пробелов. Одинаковые имена перезапишут друг друга.

### 4. Как править страницу

1. Слева выберите **Страницы** → найдите нужную в дереве (вложенность = адрес: `club/history` → `/club/history/`).
2. Измените текст/поля и сохраните.
3. **Показывать в главном меню** и **Порядок в меню** управляют верхним меню (меньше число — левее).
4. Главная страница — это страница `index`.

### 5. Как поставить черновик или снять с публикации

Включите переключатель **Черновик** и сохраните — запись/страница исчезнет с сайта после следующей пересборки. Чтобы вернуть — выключите. Удалять ничего не обязательно.

### 6. Сколько ждать публикации

Каждое сохранение запускает автоматическую сборку и выкладку. Обычно сайт обновляется через **3–6 минут**. Если сразу после сохранения ничего не изменилось — подождите и обновите страницу (Ctrl+F5).

### 7. Что делать при ошибке

| Что случилось | Что делать |
|---|---|
| Не пускает при входе / «Bad credentials» | Токен неверный, просрочен или отозван — создайте новый (п. 1.3) |
| «Not found» / нет прав сохранить | Вы не приняли приглашение в репозиторий или у токена нет права **Contents: Read and write** на `kendo-baikal` |
| Сохранили, но на сайте не появилось через 15 минут | Запись может быть в **черновиках**; проверьте переключатель. Иначе сообщите владельцу — возможно, упала сборка (вкладка **Actions** в репозитории) |
| Сохранение дало красную ошибку про поле | Проверьте обязательные поля (Заголовок, Дата) |
| Случайно испортили запись | Сообщите владельцу: любую версию можно вернуть из истории Git |
| Страница админки не открывается | Проверьте интернет; попробуйте другой браузер (Chrome/Firefox/Edge/Safari свежих версий); сообщите владельцу |

## Для владельца

### Как пригласить редактора

1. GitHub → репозиторий `tulubyev/kendo-baikal` → **Settings** → **Collaborators** → **Add people** → введите логин → роль **Write**.
2. Человек принимает приглашение и создаёт токен по инструкции выше.

### Как отозвать доступ

1. **Settings** → **Collaborators** → рядом с человеком **Remove**. Токен без доступа к репозиторию бесполезен.
2. Если токен мог утечь — попросите редактора отозвать его (или он отзовётся сам при удалении аккаунта/доступа).

### Безопасность — важно знать

- Роль **Write** даёт право менять **любой файл** репозитория, включая `Dockerfile`, workflow GitHub Actions и конфиг nginx. Эти файлы собираются и выкатываются на VPS автоматически. Поэтому приглашайте только тех, кому доверяете как соавтору сайта.
- На VPS ограниченный SSH-ключ умеет только запускать `deploy.sh` (см. `DEPLOY.md`). `deploy.sh` и `docker-compose.prod.yml` на сервере лежат копией — **они не обновляются из репозитория автоматически**, поэтому правка этих файлов в репозитории на сервер сама не попадёт.
- Рекомендуется: включить 2FA на GitHub у всех; использовать fine-grained токены только на этот репозиторий; при росте числа редакторов рассмотреть GitHub Rulesets, ограничивающие правки вне `src/content/**` и `public/uploads/**`.
- Админка не индексируется поисковиками (`noindex`, `X-Robots-Tag`) и не содержит секретов: токен хранится только в браузере редактора.
- Репозиторий публичный: **не загружайте** в админку то, что не должно быть публичным (личные данные, документы с паспортными данными и т. п.) — все загруженные файлы и вся история видны всем.

### Что не проверено вживую

Авторы конфигурации не могли открыть админку в браузере с реальным репозиторием. После первого деплоя проверьте: вход по токену, создание тестового поста (черновик), загрузку картинки, правку страницы, транслитерацию адреса, вкладку Network (нет блокировок CSP в консоли браузера). При блокировках CSP расширьте `location /admin/` в `nginx.conf`.
